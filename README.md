# Mobile Camera Placement DB

Language-agnostic hardware database of **phone and tablet front-camera location** in portrait orientation (`RIGHT`, `TOP`, or `LEFT`). Apps that pin a camera preview, punch-hole overlay, or video-call layout can look up a device by its hardware identifier without depending on a specific SDK.

License: [MIT](LICENSE).

## Camera positions

Values describe where the front camera sits when the tablet is held **in portrait** (short edges at top and bottom):

| Value | Meaning |
| --- | --- |
| `RIGHT` | Camera is on the long edge — the right side in portrait, which becomes the top edge in landscape video calls. |
| `TOP` | Camera is on the short edge (phones, mini tablets, older iPads). |
| `LEFT` | Reserved for the opposite long edge. |

Phones are almost always `TOP`. Landscape-first tablets (iPad 10th generation+, iPad Air M2+, iPad Pro M4+, Galaxy Tab S7+, Pixel Tablet, recent Android pads) use `RIGHT`.

### Inference rules

Camera placement is not a field in AppleDB or Play. Positions are inferred:

| Family | Position | Rule |
| --- | --- | --- |
| iPhone, iPod touch | `TOP` | Short-edge selfie camera in portrait |
| iPad mini (all) | `TOP` | Still short-edge |
| iPad Air M2+ | `RIGHT` | Landscape-edge from 2024 |
| iPad Pro M4+ | `RIGHT` | Landscape-edge from 2024 |
| iPad (standard) 10th gen / A16+ | `RIGHT` | First Apple slate with landscape camera (2022) |
| Older iPad / Air / Pro | `TOP` | Including 11-inch Pro 3rd and 4th gen |
| Android phones | `TOP` | Portrait-first; Fold inner cameras are a known exception |
| Galaxy Tab S7 and later (incl. FE / Lite / Ultra) | `RIGHT` | 2020+ productivity tabs |
| Pixel Tablet, OnePlus/OPPO/Xiaomi/Redmi/POCO/Honor Pad, MatePad Pro, Lenovo Tab P11/P12 | `RIGHT` | 2022+ landscape-first Android tablets |
| Other tablets (Tab A8, S6, Active, …) | `TOP` | Short-edge punch-hole / bezel camera |

### iPad trend by launch year

| Year | iPad identifiers | `RIGHT` share | What shipped |
| --- | --- | --- | --- |
| 2010–2021 | 73 | 0% | Camera on the short edge |
| 2022 | 8 | 25% | iPad 10th gen (`RIGHT`); 11/12.9 Pro 4th/6th gen still `TOP` |
| 2023 | 0 | — | No new iPad |
| 2024 | 10 | 80% | Air M2 + Pro M4 `RIGHT`; mini A17 Pro still `TOP` |
| 2025–2026 | 14 | 100% | Air M3/M4, Pro M5, iPad A16 |

Android tablets follow the same industry shift about two years earlier: Galaxy Tab S7 (2020) moved the selfie camera to the long edge for laptop-style video calls. Phones never did — **99.5% of the catalog is `TOP`** because phones dominate Play’s list.

## Identifier sources

`sync_sources.py` pulls catalog rows from structured public databases rather than scraping vendor HTML.

| Platform | Primary source | Why this one | Fallback |
| --- | --- | --- | --- |
| iOS | [AppleDB](https://appledb.dev) (`api.appledb.dev/device/main.json.gz`, MIT) | Identifier-keyed JSON with Wi-Fi vs Cellular names, device type, and SoC. Covers more iPad hardware strings than DeviceKit or Xcode identifier dumps. | [DeviceKit](https://github.com/devicekit/DeviceKit) `Device.generated.swift` |
| Android | [androidtrackers/certified-android-devices](https://github.com/androidtrackers/certified-android-devices) `by_model.json` (MIT) | Daily UTF-8 JSON of Google Play's official certified-device list, keyed by `Build.MODEL`. | [Google Play supported_devices.csv](https://storage.googleapis.com/play_public/supported_devices.csv) |

Not used: [KHwang9883/MobileModels](https://github.com/KHwang9883/MobileModels) (CC BY-NC-SA 4.0, incompatible with this MIT catalog) and DeviceKit as the primary iOS source (Swift enums collapse Wi-Fi/Cellular variants and lag AppleDB).

## Schema

`devices`

| Column | Type | Notes |
| --- | --- | --- |
| `id` | INTEGER | Primary key |
| `model_id` | TEXT | Unique hardware identifier |
| `market_name` | TEXT | Marketing name, e.g. `iPad Pro 11-inch (M4) Wi-Fi` |
| `platform` | TEXT | `iOS` or `Android` |
| `camera_position_portrait` | TEXT | `RIGHT`, `TOP`, or `LEFT` |
| `updated_at` | TEXT | ISO-8601 UTC; stable across rebuilds |

## Build locally

Python 3.9+ with no third-party packages:

```bash
python build_data.py
```

This reads `schema.sql`, writes `output/devices.db`, and exports the same rows to JSON (indent 2), CSV, and XML (`<devices>` / `<device>`).

## Monthly auto-update

`.github/workflows/monthly-update.yml` runs on the 1st of each month (and via `workflow_dispatch`):

1. Fetch [AppleDB](https://api.appledb.dev/device/main.json.gz) and map every iPhone / iPad / iPod hardware identifier.
2. Fetch [androidtrackers `by_model.json`](https://github.com/androidtrackers/certified-android-devices) and map every phone/tablet `Build.MODEL` (skip TV / Wear / Chromebook).
3. Refresh marketing names. Infer `camera_position_portrait` for **new** identifiers; leave curated positions unchanged.
4. Rebuild `/output` (including `stats.json`) and open a pull request.

Run the same sync locally:

```bash
python sync_sources.py
python build_data.py
```

Camera placement is not published by AppleDB or Google Play. Positions use the family rules above. Review `RIGHT` rows for newly launched tablet families in the monthly PR.

## Using the data

JSON:

```json
{
  "id": 1,
  "model_id": "iPad16,3",
  "market_name": "iPad Pro 11-inch (M4) Wi-Fi",
  "platform": "iOS",
  "camera_position_portrait": "RIGHT",
  "updated_at": "2026-08-24T00:00:00Z"
}
```

Look up by `model_id`. If a device is missing, it was likely skipped as non-mobile (TV, watch, empty Play name) — do not assume `TOP`.
